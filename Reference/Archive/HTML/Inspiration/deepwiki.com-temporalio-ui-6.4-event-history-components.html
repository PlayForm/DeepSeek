This page documents the components and logic used to display, filter, and visualize workflow event histories. The system handles raw event data, logical event groups, pending activities, and complex payload decoding.

Overview

The Event History system is built around a centralized table view that can switch between different visualization modes: a standard feed, a compact grouped view, and a raw JSON view. It integrates a visual timeline graph to show event relationships and durations.

Key Components

EventSummary

The top-level controller for the history view. it manages the view state (feed, compact, or json) and prepares the items for display based on sorting and filtering preferences.

  • View Switching: Uses eventViewType store to toggle between EventSummaryTable and WorkflowHistoryJson. src/lib/components/event/event-summary.svelte80-98
  • Item Preparation: Combines history events with pendingActivities and pendingNexusOperations from the workflow execution. src/lib/components/event/event-summary.svelte42-58

Sources: src/lib/components/event/event-summary.svelte37-53

EventSummaryTable

A paginated container that renders rows based on the type of event (regular event, EventGroup, PendingActivity, or PendingNexusOperation).

  • History Graph Integration: Renders the HistoryGraph (lines-and-dots SVG) alongside the table when not in compact mode. src/lib/components/event/event-summary-table.svelte70-71 src/lib/components/event/event-summary-table.svelte137-139
  • Dynamic Columns: Adds a "Billable Actions" column when running in a Cloud environment (isCloud). src/lib/components/event/event-summary-table.svelte102
  • Row Rendering: Iterates over visibleItems and conditionally renders EventSummaryRow, PendingActivitySummaryRow, or PendingNexusSummaryRow based on the item type. src/lib/components/event/event-summary-table.svelte161-197

Sources: src/lib/components/event/event-summary-table.svelte76-146

EventSummaryRow

Renders a single row in the history table. It calculates elapsed time, duration (for groups), and identifies primary/secondary attributes for the summary view.

  • Primary Attributes: Uses getPrimaryAttributeForEvent to find the most relevant data point (e.g., activityType or signalName). src/lib/components/event/event-summary-row.svelte142-147
  • Status Styling: Applies specific background colors for failure, canceled, and terminated states. src/lib/components/event/event-summary-row.svelte114-116
  • Local Activity Decoding: Asynchronously decodes local activity markers on mount using decodeLocalActivity. src/lib/components/event/event-summary-row.svelte200-207
  • System Nexus Integration: Resolves system Nexus events and their display names and links using resolveSystemNexusEvent. src/lib/components/event/event-summary-row.svelte118-127

Sources: src/lib/components/event/event-summary-row.svelte108-122 src/lib/components/event/event-summary-row.svelte188-197 src/lib/components/event/event-summary-row.svelte200-207

Visualizations: Timeline Graph

The "Lines and Dots" visualization provides an SVG-based timeline of the workflow execution.

HistoryGraph

The HistoryGraph component is responsible for rendering the timeline visualization. It takes groups and history as props and displays a graphical representation of the workflow events. src/lib/components/event/event-summary-table.svelte137

TimelineGraphRow

Renders the individual dots and lines for an EventGroup.

  • Dots: Represent specific events in time.
  • Lines: Represent the duration between events (e.g., from ActivityTaskScheduled to ActivityTaskCompleted).
  • Pending Lines: Renders a dashed or transparent line for activities currently in flight or paused. src/lib/components/lines-and-dots/svg/timeline-graph-row.svelte205-234

Data Processing & Attributes

Attribute Selection Logic

The UI uses a prioritized list to determine which attributes to show in the summary row to avoid cluttering the interface. getPrimaryAttributeForEvent and getSecondaryAttributeForEvent are key functions for this.

PriorityAttribute Keys
PrimaryactivityType, signalName, workflowType, result, failure, input
SecondarytaskQueue, attempt, identity, scheduledTime, expirationTime

Sources: src/lib/utilities/get-single-attribute-for-event.ts248-260

Payload Decoding

The PayloadInline component (used within EventDetailsRow) handles the transformation of raw Temporal payloads into human-readable strings or JSON objects.

  • Link Detection: displayLinkType identifies if an attribute value should be rendered as a link to another Workflow Execution, Task Queue, or Nexus Endpoint. src/lib/utilities/get-single-attribute-for-event.ts172-179
  • Local Activity: Local activities are stored in markers and require specific parsing logic via decodeLocalActivity. src/lib/utilities/decode-local-activity.ts
  • EventDetailsRow: This component displays a single attribute key-value pair. It uses PayloadInline for raw payloads and EventDetailsLink for linkable values. src/lib/components/event/event-details-row.svelte46-65

Pending Operations

Pending operations (Activities and Nexus) are displayed both as cards in dedicated tabs and as rows within the event history to provide context on what the workflow is currently blocked on.

PendingActivitySummaryRow

Specifically handles the display of activities that have not yet completed. It shows:

  • Attempts: The current attempt count. src/lib/components/event/pending-activity-summary-row.svelte40
  • Next Retry: Calculated time until the next attempt if the activity is backing off. src/lib/components/event/pending-activity-summary-row.svelte41
  • Last Failure: The error message from the previous attempt. src/lib/components/event/pending-activity-summary-row.svelte42

Sources: src/lib/components/event/pending-activity-summary-row.svelte1-10

PendingNexusSummaryRow

Similar to PendingActivitySummaryRow, this component displays details for pending Nexus operations. It shows the operation's attempt count and other relevant information. src/lib/components/event/pending-nexus-summary-row.svelte1-10

Sources: src/lib/components/event/pending-nexus-summary-row.svelte1-10

Event Filtering and Sorting

Filtering is managed through Svelte stores that react to URL parameters and user input.

  • Category Filtering: Events can be filtered by category (e.g., Activity, Timer, Signal) via the eventCategoryFilter store. This store is updated based on the category URL search parameter. src/lib/components/event/event-summary.svelte36-40
  • Status Filtering: The eventStatusFilter allows users to see only failed or pending events. This filter is applied in EventSummaryTable using getFailedOrPendingGroups or getFailedOrPendingEvents. src/lib/components/event/event-summary-table.svelte81-84
  • Sorting: The eventFilterSort store controls whether history is displayed in ascending or descending order. src/lib/components/event/event-summary.svelte31
