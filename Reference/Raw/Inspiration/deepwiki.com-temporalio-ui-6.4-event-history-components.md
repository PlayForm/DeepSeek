This page documents the components and logic used to display, filter, and visualize workflow event histories. The system handles raw event data, logical event groups, pending activities, and complex payload decoding.
## Overview
The Event History system is built around a centralized table view that can switch between different visualization modes: a standard feed, a compact grouped view, and a raw JSON view. It integrates a visual timeline graph to show event relationships and durations.

## Data Processing & Attributes
### Attribute Selection Logic
The UI uses a prioritized list to determine which attributes to show in the summary row to avoid cluttering the interface. `getPrimaryAttributeForEvent` and `getSecondaryAttributeForEvent` are key functions for this.  
| Priority  | Attribute Keys  |  
| --- | --- |  
| **Primary**  |  `activityType`, `signalName`, `workflowType`, `result`, `failure`, `input`  |  
| **Secondary**  |  `taskQueue`, `attempt`, `identity`, `scheduledTime`, `expirationTime`  |

  * **Category Filtering** : Events can be filtered by category (e.g., Activity, Timer, Signal) via the `eventCategoryFilter` store. This store is updated based on the `category` URL search parameter.
