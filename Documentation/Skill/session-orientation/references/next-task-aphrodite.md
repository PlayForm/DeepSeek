# The Next Session's Task (the Aphrodite Site)

> Source: SKILL.md, section 6 ("THE NEXT SESSION'S TASK (the Aphrodite

> This file carries the full philosophy; SKILL.md only points here.

## The Rule

The next session authors `~/Developer/Application/PlayForm/Aphrodite/Site` -
an ADVANCED ITERATION and richer-information variation of the website
workflows built in this repository.

The path is normative: the Aphrodite repository lives at
`~/Developer/Application/PlayForm/Aphrodite`. An earlier
`~/Developer/Application/Aphrodite` path is STALE - use the
PlayForm-parented path.

The reference is THIS repo's `Site/`: an Astro static site in the
"Technical Minimalist Harness" design (blue + white only, Inter + IBM Plex
Mono, 1px hairlines, zero elevation) with 21 pages - the landing page, the
plugins registry + 12 plugin detail pages, the workbench (live stream-gate
terminals), versions, setup, flavors, matrix, models, and the case study.

Aphrodite's Site must be a BETTER + more-informed variation of those
workflows: same laws, richer documentation, evolved design.

## Why: The Full Philosophy

1. **A named next task prevents drift at session start.** A fresh session's
   default failure is inventing work: re-auditing, "improving" random files,
   or re-running finished plans. A stated next task gives every session the
   same first objective, and the orientation protocol makes it part of what
   a session must be able to recite.
2. **The stale path is a planted trap.** An earlier path
   (`~/Developer/Application/Aphrodite`) once pointed at the repository; it
   is stale. Sessions that use it will read or write a wrong or absent tree.
   The PlayForm-parented path
   (`~/Developer/Application/PlayForm/Aphrodite`) is the only correct one -
   that is why the rule calls the path out explicitly rather than letting
   memory supply it.
3. **The reference is concrete, not aspirational.** "Build a better site"
   is unworkable without a reference implementation. THIS repo's `Site/` is
   the reference: its design system (blue + white only; Inter + IBM Plex
   Mono; 1px hairlines; zero elevation), its page inventory (21 pages,
   enumerated), and its workflows are the baseline Aphrodite's Site must
   exceed.
4. **"Better + more-informed" defines the direction of variation.** Same
   laws (the lane laws below and this skill's laws apply unchanged), richer
   documentation (more information per page), evolved design (the aesthetic
   progresses from the baseline). The instruction is not "copy the site"
   and not "invent a new design" - it is an advanced iteration.

## Examples

### Good

- A session starts an Aphrodite task by confirming the target path
  `~/Developer/Application/PlayForm/Aphrodite/Site` exists before any
  writing.
- A session re-reading this repo's `Site/` pages enumerates the 21 pages as
  its reference checklist for what Aphrodite's Site must cover and exceed.

### Bad

- A session begins authoring at `~/Developer/Application/Aphrodite/Site` -
  the stale path; anything written there is written to the wrong place.
- A session treats the task as "rebuild this repo's Site/ exactly" - the
  mandate is a better, more-informed variation, not a copy.
- A session invents a new visual language for Aphrodite's Site instead of
  evolving the "Technical Minimalist Harness" design.

## Exceptions

- None documented. The task statement and the path are fixed points of the
  orientation; a user instruction can redirect the session's work for that
  session, but the recorded next task remains as stated until the user
  changes it.

## Failure Modes

- Stale-path authoring: work placed under the old
  `~/Developer/Application/Aphrodite` path; the deliverable is lost or
  wrong-tree.
- Copy-instead-of-iterate: reproducing this repo's Site/ verbatim and
  calling it done - the mandate requires better + more-informed.
- Design drift: abandoning the blue/white, Inter + IBM Plex Mono, hairline,
  zero-elevation system for an invented aesthetic, breaking continuity with
  the reference.
- Missing reference reading: starting Aphrodite's Site without studying
  this repo's `Site/` (its 21 pages and workflows), so the "variation" has
  no baseline.

## Arbiters

- The path check: only `~/Developer/Application/PlayForm/Aphrodite` (and
  its `Site/`) is the target; any other Aphrodite path in a session's work
  is evidence of the stale-path failure.
- The reference inventory: this repo's `Site/` 21-page list (landing,
  plugins registry + 12 plugin detail pages, workbench with live
  stream-gate terminals, versions, setup, flavors, matrix, models, case
  study) is the checklist a plan for Aphrodite's Site must address and
  exceed.
- The lane laws (see ./references/lane-laws.md) apply to the Aphrodite
  build unchanged; a build violating them is invalid regardless of output
  quality.
