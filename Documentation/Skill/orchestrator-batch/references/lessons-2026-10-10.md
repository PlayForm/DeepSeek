## The Rule

The 2026-10-09/10 workflow taught seven lessons. The user instructed:
"learn from this workflow, preserve the necessary skills, + erase all
temporary handoff documentation and temporary files." The handoff docs
(Documentation/Handoff/) are TEMPORARY by that decree - erased at the
session's close; the SKILL.md, the Plans/, and the Reports/ stay as the
durable records. The lessons, each with its full content:

### Lesson 1 - THE SKILL IS NOT IN THE SESSION CATALOG: LOAD IT FROM THE REPO FIRST

The orchestrator slipped the non-execution law (ran lychee, edited a
README, committed 23a313d, byte-grepped and curled the dev server) partly
because the skill was not registered in the session's catalog. The
session-start ritual must read the skill from the tree
(Documentation/Skill/orchestrator-batch/SKILL.md) before ANY delegation.
The slip record: TOMORROW-REVIEW.md section 9.
(See also arbiters-are-the-lanes-own.md for the non-execution law it
guards.)

### Lesson 2 - THE IDLE-LANE SEATING PROTOCOL WORKS

Launch with the fully self-contained spec + the routing
(cloudflare-workers-ai / @cf/zai-org/glm-5.3-flash, low), then send_message
the seating line ("ACK: SPEC RECEIVED - IDLE"), activate with "ACTIVATE"
when a slot frees, amend mid-flight with "SPEC AMENDED" when the new
feedback lands on an active lane's surface (the spec-reconfiguration
authority). The 2026-10-09 evening queue ran 2 active + up to 4 idle
cleanly.

### Lesson 3 - THE STALE-ARTIFACT CLASS

Several user reports (the once-published install block, the "lost" red
Pause cursor, the duplicated homepage buttons, the missing media queries,
the broken quote glyphs) were STALE browser/dev-server caches or transient
intermediate commits - not code defects. The lane's evidence-gathering
(fetch the live page, byte-compare the
deployed CSS, count the occurrences in the BUILT output) resolved them
without a fix. The orchestrator relays the verdict + the user's remedy
(hard refresh / service-worker unregister) verbatim.

### Lesson 4 - THE "NO FIX NEEDED" VERDICT IS A RESULT

The media-query question was BY-DESIGN (fluid clamp typography, the
legacy-to-range minifier translation, the space-stripped
`@media (width>=768px)`); the red pause cursor was never removed
(b9138c89, `git log -S` proof); the raw-marker brace WAS a real fix
(FileIcon.ts:161 regex). The lane reports the evidence either way; the
orchestrator does not pre-judge.

### Lesson 5 - THE SITE'S AUTO-COMMIT HOOK

The Site repo has a governor hook that auto-commits lane changes mid-build
and can sweep one lane's edits into a sibling lane's commit. The lanes
split history (soft reset, two clean commits) when that happens; the
orchestrator checks for the split in the final report.

### Lesson 6 - THE UNICODE-GLYPH RULE BITES EVERY WRITE

The normalize hooks are active in the profile: the plain write tool's
placements get their glyphs replaced. The lanes use raw-write (exempt) or
the identity-exempt edit tool for real unicode. The glyph-loss report
class (Mapping/QuotesMap tables) is caused by this exact mechanism.

### Lesson 7 - THE PUBLISH CLOSE-OUT

The tolerance pattern (continue-on-error + `|| true`) absorbs the E403s of
already-published packages; the run status may report green while
individual publishes fail - the registry (curl dist-tags.latest) is the
arbiter, not the run badge. The 25/25 publish completed 2026-10-09.

## Why: The Full Philosophy

1. **Lessons are preserved in the skill, not in the session.** The user's
   erase instruction drew the line precisely: transient state (handoff
   docs, temporary files) dies at the session's close; durable knowledge
   (skills, Plans/, Reports/) survives. These seven lessons are the
   durable distillation of the 2026-10-09/10 workflow.
2. **Lesson 1 is about the skill-loading failure chain:** a skill missing
   from the catalog is not a minor inconvenience - the un-loaded
   orchestrator then violated the non-execution law repeatedly before
   anyone noticed. The ritual (read the skill from the tree first) is
   cheap insurance against that chain.
3. **Lesson 2 validates the idle pattern empirically:** the 2-active +
   4-idle queue ran cleanly, which is why the two-active regime
   (the-two-active-regime.md) is confident in its mechanics.
4. **Lesson 3 teaches evidence before fixes:** the most common "bugs" in a
   web batch are stale artifacts. Evidence-gathering (live fetch, byte
   compare, built-output counts) is cheap; a code fix for a cache artifact
   is a regression.
5. **Lesson 4 protects "no fix needed" as a first-class outcome:** the
   orchestrator must not pressure lanes into fixes. Evidence either way
   (by-design, never-removed, real-fix) is the result; the commit hash
   (b9138c89) and the file:line (FileIcon.ts:161) are how the evidence is
   recorded.
6. **Lesson 5 is about tooling acting in the background:** the auto-commit
   hook writes history while lanes work; attribution requires the split
   check. History hygiene is the orchestrator's final-report duty.
7. **Lesson 6 is about the write-path environment:** the normalize hooks
   replace glyphs on plain writes; raw-write/edit-exempt paths are the
   sanctioned routes for real unicode. The Mapping/QuotesMap glyph-loss
   reports trace to exactly this.
8. **Lesson 7 is about trusting the right arbiter:** exit codes and run
   badges are not ground truth when tolerance patterns absorb errors; the
   registry's dist-tags.latest is.

## Examples

### Good

- Session start: the catalog lacks the skill -> the ritual reads
  Documentation/Skill/orchestrator-batch/SKILL.md from the tree before any
  delegation.
- User reports "the homepage buttons are duplicated" -> the lane fetches
  the live page and counts occurrences in the BUILT output before writing
  any fix -> verdict: stale cache; relay the remedy (hard refresh) verbatim.
- A lane suspects unicode loss in Mapping/QuotesMap -> it re-writes the
  table via raw-write (exempt path) and verifies the glyphs survived.
- After a publish run shows green: curl the registry dist-tags.latest and
  verify each of the 25 packages actually landed.

### Bad

- Delegating before loading the skill from the tree (the lesson-1 chain).
- Writing a fix for a report that evidence gathering would have resolved
  as a stale artifact.
- Treating "no fix needed" as a failed task instead of a valid result with
  evidence.
- Trusting a green run badge while individual publishes E403'd away.

## Exceptions

- The temporary-docs decree has a within-session exception: during a live
  session the handoff docs are kept fresh (see session-resume-protocol.md);
  the ERASE happens at the session's close.
- Lesson 4's "no fix needed" applies when evidence proves it (hash, file
  line, built-output count) - not as a blanket excuse to skip work.

## Failure Modes

- Catalog-miss: the skill not loaded -> non-execution violations repeat
  (the exact 2026-10-09 chain).
- Fixing stale artifacts: code churn, regressions, and a user whose real
  issue (the cache) persists.
- Glyph loss on plain writes: Mapping/QuotesMap tables silently corrupted
  - the report class lesson 6 names.
- Green-badge blindness: publishes silently failed; the "25/25 done"
  claim is false until the registry confirms.

## Arbiters

  before the first delegation; the slip record is TOMORROW-REVIEW.md section 9.
- Lesson 2: the queue record shows ACK/ACTIVATE/SPEC AMENDED lines and the
  lane counts (2 active + up to 4 idle ran cleanly on 2026-10-09).
- Lesson 3: the lane's verdict must carry its evidence (live fetch, byte
  compare, built-output counts) before any fix is written.
- Lesson 4: "no fix needed" verdicts must cite evidence (b9138c89 for the
  pause cursor; FileIcon.ts:161 for the raw-marker brace fix).
- Lesson 5: the final report includes the history-split check for the
  Site repo.
- Lesson 6: unicode-bearing files are written via raw-write or the

- Lesson 7: the registry (dist-tags.latest via curl) confirms the
  publishes; the run badge alone is not accepted.
