# THE WORKSPACE FAMILY - THE ANY-FILE ADAPTERS (NOT JUST .TS)

> This is a granular document of the Workspace Plugin Family Decomposition. The parent hub is
> Documentation/Plans/WORKSPACE-PLUGIN-FAMILY-DECOMPOSITION.md. THE FRAMING (binding): the workspace
> family is the DEEPSEEK HARNESS'S OWN REFACTORING into the WORKSPACE-CENTRIC RUNTIME, powered by
> the @playform plugin family, and never a single plugin.

---

- **THE SCOPE**: the system applies to ANY TYPE of halted process, which includes the .ts files (the
  TypeScript language service), the .rs files (the rust-analyzer), the .docx files (the OOXML and
  word processing), the images, the binaries, and the data files.
- **THE REGIME**: the adapters work in the workspace regime (the third axis) and make ANY file type
  OPERABLE in the workspace through the file's knowledge graph. The OS execution axis stays
  orthogonal, so a .rs file runs under rustc in the execution regime while its adapter serves the
  workspace regime.
- **THE MANTRA**: THINK ADAPTERS, THINK GRAPHS, THINK METHODOLOGY, because each file type gets its
  adapter that produces the file's KNOWLEDGE GRAPH (the blocks, the references, the semantics, and
  the dependencies).
- **THE MAIN EVIDENCE**: THE CODE BLOCK is the universal atom, so start small with the code blocks
  and expand from there.
- **THE RESULT**: each file is a knowledge graph, managed by code fully and powered by the DeepSeek
  Harness.
- **THE ADAPTER'S CONTRACT** (the three verbs):
    - **observe** - the file's representation;
    - **propose** - the operations the type supports (rename, connect, replace, and transform per
      the type's semantics);
    - **reconcile** - the applied results.
